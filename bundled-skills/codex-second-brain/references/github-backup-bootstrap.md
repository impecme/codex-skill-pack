# GitHub 私有仓库人工备份引导（懒人包 05）

本参考仅用于用户已选择懒人包 `05` 的首次配置。按 [setup 工作流](workflows.md) 调用；执行前遵守[安全、同步与自动化规则](safety-and-sync.md)，并确认[本机 Syncthing 引导](syncthing-bootstrap.md)已完成。这里只配置本机 Git 元数据和 GitHub 私有远端，不安装 Git/GitHub CLI，不执行快照备份。

## 固定设备职责

- 用户的个人电脑是唯一 Git 备份设备：其设备配置使用 `backupMode: "github-manual"`、`gitBackupDevice: true`；Vault 的 `.git` 只保留在这台电脑。
- SSH 服务器使用 `gitBackupDevice: false`，不得在服务器初始化或维护该 Vault 的 `.git`。
- Syncthing 继续同步 Vault 内容；`.git` 必须由本机 `.stignore` 排除。GitHub 是人工云端备份，不是实时同步通道。
- 本引导不创建 `weekly` 自动化任务。新设备配置的 `weeklyAutomationId` 保持 `null`；若现有配置或调度器显示已有周任务，先报告并等待用户决定，不静默删除或改动。
- 先核实当前 05 对话运行在用户指定的个人电脑，并确认服务器保持非备份角色。若设备身份或任一设备角色不明确、配置冲突，停止，不猜测或改写配置。修改设备配置前展示目标文件及精确差异并取得确认。

## 只读检查与仓库选择

1. 从现有设备配置确认 Vault 路径、设备身份及备份角色；检查 Git 和可选 GitHub CLI 是否可用，并只读检查 Vault 是否已有 `.git`、工作区状态及远端。不得输出或索取凭证。
2. 如果已有远端，核实它对应用户选择的仓库且仓库为私有。已存在且唯一、可验证的私有远端可以复用。多个远端候选、公开仓库、无法验证的远端或指向其他用途的 `origin` 都要停下，请用户选择；不得擅自覆盖远端。
3. 若没有可复用远端，先让用户明确选择一个现有私有仓库，或明确确认创建一个新仓库，并确认 owner/name 与私有可见性。创建仓库属于 GitHub 外部写入，只能在该项明确确认后进行。
4. GitHub CLI 已安装且已在本机完成认证时，可用它只读核实远端 URL 和私有可见性；不要展示认证材料。若 CLI、认证或 Git 不可用，不要安装工具或索取 Token/私钥：让用户在本机浏览器自行登录 GitHub，选择或明确创建私有仓库，再提供不含凭证的 clone URL；Git 不可用时，说明需由用户先在本机安装/配置 Git。
5. 若选中的远端已有内容或提交，先核实其内容和历史确实属于此 Vault 且与本地历史相容。本机尚无 `.git` 时无法核对本地提交关系；此时停止，请用户选择空仓库或确认专门的历史衔接方案。其他内容/历史不明或不相容的情况也停止并交由用户决定；不自动 pull、合并、重置、改写历史或强推。

## 本机配置与确认

- 保留 Vault 中现有文件、`.gitignore`、`.stignore` 及已有 Git 历史；不因 Vault 非空而覆盖或清理内容。若 `.git` 已存在，检查并复用，不重新初始化。
- 若个人电脑上的 Vault 尚无 `.git`，先向用户展示实际绝对目标路径和差异，例如：`<Vault>/.git：不存在 → 初始化本机 Git 元数据`。说明不会暂存、提交或推送任何内容；取得针对这项初始化的明确确认后才可执行 `git -C "<Vault>" init`。
- 若需添加远端，先展示实际 Vault 路径、远端名称以及精确变更，例如：`origin：不存在 → <已核实的私有仓库 clone URL>`。取得明确确认后才可添加。已有 `origin` 不匹配时不执行 `set-url`；先让用户选择并确认具体变更。远端 URL 不得包含 Token、密码或其他凭证；发现内嵌凭证时遮蔽内容并停止，交由用户在本机安全处理。
- 目标已符合上述配置时不写入，按已就绪报告。任何目标在确认后发生变化，重新检查并展示新差异，再取得确认。

## 完成状态

只有在个人电脑和服务器角色已确认、个人电脑本地 `.git` 存在、唯一远端已核实为私有仓库且 `.git` 被 Syncthing 排除后，才报告“配置就绪”。这不代表已有云端快照：快照仍待用户之后手动操作。以后每次备份都先查看并展示变更；`git add`、`git commit`、`git push` 分别等待用户明确确认，任何一步都不自动执行。提交确认不包含推送确认。
