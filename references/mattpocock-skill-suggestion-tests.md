# Matt Pocock 非自动调用 Skill 建议规则验收用例

维护或调整 `01` 的全局建议区块时，用这些场景检查触发边界。它们验证的是建议行为，不是上游 Skill 的客户端可发现性或运行功能。

| 场景 | 对话意图 | 预期 |
| --- | --- | --- |
| `ask-matt` | 用户在多种工程方法之间犹豫，询问采用哪种工作流及理由 | 只建议 `ask-matt`，说明其适合顾问式判断，然后等待选择 |
| `grill-with-docs` | 用户说目标还不清楚，希望通过追问厘清并整理成项目文档 | 只建议 `grill-with-docs`，然后等待选择 |
| `implement` | 用户给出已确认的 spec/计划并明确要求据此实现 | 只建议 `implement`，然后等待选择 |
| `improve-codebase-architecture` | 用户要求系统检查现有代码库的架构问题并提出整体改进 | 只建议 `improve-codebase-architecture`，然后等待选择 |
| `setup-matt-pocock-skills` | 用户明确要求为该项目首次配置 tracker、labels 和工程文档 | 只建议 `setup-matt-pocock-skills`，不得直接初始化项目 |
| `to-spec` | 需求讨论已稳定，用户要求生成正式、带验收标准的规格 | 只建议 `to-spec`，然后等待选择 |
| `to-tickets` | 用户已批准 spec，要求拆成有依赖关系的执行 tickets | 只建议 `to-tickets`，然后等待选择 |
| `triage` | 用户交来尚未分流的 issue/PR 队列，要求分类和排优先级 | 只建议 `triage`，然后等待选择 |
| `wayfinder` | 用户面对跨阶段、目标和下一步都不清楚的长期工程事项 | 只建议 `wayfinder`，然后等待选择 |
| 不应触发：普通实现 | 用户要求直接完成一个范围清晰的小改动，未给出需执行的 spec/ticket | 不建议 `implement`；直接处理任务 |
| 不应触发：术语解释 | 用户只问某个 Skill 是什么、有什么区别 | 解释 Skill，不推荐调用任何一项 |
| 不应触发：一般代码评审 | 用户只要求评审一组具体 diff | 不建议上述九项；按一般代码评审处理 |
| 不应触发：新仓库 | 用户在新仓库提出一个普通问题，但未要求 tracker/labels/docs 初始化 | 不建议 `setup-matt-pocock-skills` |
| 不应触发：复杂但清楚 | 用户给出明确验收标准和单一实施路径，即使任务较大 | 不因任务规模或“复杂”一词推荐 `wayfinder` |

还需验证交互约束：一阶段只推荐一个最匹配的 Skill；用户拒绝后不再重复并继续普通工作；用户已点名时不重复征求许可；后续进入不同阶段时只在匹配新的 Skill 时推荐一次。任何建议都不得改写或删除上游的自动调用限制。

## 受管区块安装验收

| 目标文件状态 | 操作/选择 | 预期 |
| --- | --- | --- |
| `AGENTS.md` 不存在 | 展示待创建内容，用户确认 | 新建文件并写入一份完整建议区块；报告 `installed` |
| 已有 `AGENTS.md`，无 Matt 标记 | 展示追加差异并获得确认 | 原有内容不变，只在末尾追加区块 |
| 已有完全相同的 Matt 区块 | 重复安装 | 不写文件、不重复追加；报告 `already-current` |
| 已有第二大脑受管区块 | 安装 Matt 区块 | 两区块各保留一份；不改动第二大脑区块及区块外文本 |
| Matt 区块内容需更新 | 展示区块内差异并获得确认 | 只原位更新 Matt 区块；其他内容逐字保持 |
| 起止标记残缺、重复、嵌套或次序错误 | 尝试安装/更新 | 不改文件，报告 `pending`；18 个 Skill 仍可独立安装 |
| 存在遮蔽基础文件的 `AGENTS.override.md` | 安装建议区块 | 不读写 override 内容作为目标；可经确认更新基础 `AGENTS.md`，并报告有效规则 `blocked` |
| 用户拒绝合并或选择跳过 | 安装 `01` | 保持 `AGENTS.md` 不变，建议区块报告 `skipped`；Skill 目录安装按用户选择独立处理 |
| 更新 `00` 的工作流规则 | 基础文件已有任一懒人包受管区块 | 除冲突规则要求停止的损坏标记外，保留所有现存有效受管区块，不静默删除 |
